# Threat model

## 보호 대상

관리자 키, 사용자 토큰, 공급자 자격증명, 모델 권한, 사용량/감사 데이터와 내부 공급자 접근입니다. 프롬프트와 응답은 통과 데이터이며 저장 대상이 아닙니다.

## 신뢰 경계와 통제

- 외부/내부 클라이언트 → Gateway: Bearer 토큰, 만료/폐기, 쿼터, RPM, 동시성, 1 MiB JSON 제한
- 관리자 → 관리 API: timing-safe 관리자 키 비교, 입력 검증, 관리자 정의 리터럴 필터만 허용
- Gateway → 등록 공급자: 관리자 등록 URL만 호출, 자격증명 포함 URL 거부, redirect 미추적, timeout/disconnect 취소
- Gateway → SQLite/로그: prepared statement, 프롬프트·응답·오류 본문과 비밀 미저장. 필터 실패는 기존 요청 메타데이터와 `error_type=filter`만 기록

콘텐츠 필터는 임의 코드, 정규식 또는 외부 정책 서버를 실행하지 않습니다. 입력 차단은 일치한 원문을 공급자에게 보내지 않고, 입력 마스킹은 공급자 요청 복사본의 대상 텍스트만 `[FILTERED]`로 치환합니다. 출력 마스킹도 chat content만 대상으로 하며 tool/function arguments와 비텍스트 part는 검사하지 않습니다. 런타임 요청 기록에는 규칙 ID·이름, 패턴, 일치 내용, 프롬프트 또는 응답을 저장하지 않습니다. 관리자 CRUD 감사에는 대상 필터 ID와 변경된 필드명만 저장하며 패턴 값은 저장하지 않습니다.

## 잔여 위험

- DB에 저장한 공급자 키는 암호화되지 않으므로 호스트/DB 파일 권한이 침해되면 노출됩니다. 환경 변수 사용을 권장합니다.
- 단일 관리자 공유 키는 개인별 관리자 추적을 제공하지 않습니다.
- 프로세스 메모리 rate limit은 재시작 시 초기화됩니다.
- TLS와 네트워크 분리는 배포 환경 책임입니다.
- 악성 공급자는 응답 본문으로 민감정보를 반환할 수 있습니다. 지정한 출력 리터럴과 대상 chat content 외의 값은 클라이언트에 전달되며 Gateway는 응답을 저장하지 않습니다.
- 필터 패턴은 매칭을 위해 관리 API, SQLite와 백업에 평문으로 존재하고 과거 백업에는 수정·삭제 전 값도 남습니다. 실제 비밀, 프롬프트 또는 응답 예시를 패턴으로 등록하지 말고 DB·백업 접근과 보존을 제한해야 합니다.
- 리터럴 content 필터는 범용 DLP가 아닙니다. 인코딩·변형된 값, tool/function arguments, 이미지·오디오와 기타 비대상 필드의 유출은 막지 못합니다.
