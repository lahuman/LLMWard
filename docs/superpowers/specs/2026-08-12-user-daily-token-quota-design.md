# 사용자 일일 토큰 한도에서 0을 무제한으로 처리

## 목표

사용자의 `max_daily_input_tokens`와 `max_daily_output_tokens` 기본값을 신규 사용자에 한해 0으로 바꾼다. 각 값은 서로 독립적이며, 0이면 해당 방향의 일일 한도를 적용하지 않고 양수이면 현재처럼 그 값까지 사용하도록 제한한다. 기존 사용자에게 저장된 한도는 변경하지 않는다.

## 결정

지원되는 사용자 생성 경로인 관리 API가 두 quota 값을 항상 명시해 저장하므로 SQLite `users` 테이블을 재작성하거나 schema version을 올리지 않는다. 관리 API의 기본값과 관리 화면의 기본값을 0으로 바꾸고, 시작 시 사용자 데이터 검증과 런타임 quota 로직이 0을 정상적인 무제한 표식으로 받아들이게 한다.

`NULL`이나 별도 무제한 플래그는 추가하지 않는다. 요청된 0 표식을 그대로 사용해 새 컬럼, 설정, 추상화를 만들지 않는다.

## 동작

- 사용자 생성 요청에서 입력 또는 출력 quota가 생략되면 각각 0을 저장한다.
- 사용자 생성과 수정 요청은 0 이상의 safe integer만 허용한다. 음수, 소수, 문자열, 범위를 벗어난 정수는 400 응답으로 거부한다.
- 입력 quota가 0이면 누적 입력 토큰에 따른 요청 거부를 생략한다. 양수이면 기존과 같이 누적 사용량이 한도에 도달한 뒤 후속 요청을 거부한다.
- 출력 quota가 0이면 일일 잔여 출력량에 따른 `max_tokens` 축소와 요청 거부를 생략한다. 모델 한도와 요청의 `max_tokens`는 계속 적용한다.
- 출력 quota가 무제한이어도 기존 quota reservation row를 요청·모델 최대 출력 토큰으로 생성한다. 공급자 초과 출력 검증과 성공, 오류, timeout, disconnect, shutdown의 멱등 cleanup 경로를 그대로 유지한다.
- 입력과 출력 quota는 독립적으로 적용한다. 한쪽이 0이고 다른 쪽이 양수인 구성도 지원한다.
- `GET /dashboard/usage`의 `remainingInput` 또는 `remainingOutput`은 해당 quota가 무제한이면 0을 반환한다. 이 필드에서도 0은 무제한 표식이다.
- 관리 화면의 신규 사용자 입력 기본값과 최소값을 0으로 바꾸고, 사용자 목록의 0 quota는 `Unlimited`로 표시한다. 편집 프롬프트에서도 0을 입력할 수 있다.
- 기존 사용자 값은 자동 변경하지 않는다.

## 영속성과 호환성

현재 DB 컬럼은 0 저장을 막는 CHECK 제약이 없다. 따라서 테이블 재작성 없이 0을 저장할 수 있다. 마이그레이션의 사용자 데이터 사전 검증만 quota 값을 양의 정수에서 0 이상의 정수로 완화해, 0을 저장한 DB가 재시작 때 거부되지 않게 한다.

기존 양수 quota의 제한, 동시 출력 예약, 사용량 기록, 토큰 인증 및 다른 rate/concurrency 제한의 동작은 변경하지 않는다.

## 검증

- quota를 생략한 신규 사용자의 두 값이 0인지 검증한다.
- 생성과 수정 API가 0을 허용하고 음수·비정수·범위 초과값을 거부하는지 검증한다.
- 입력·출력이 모두 0인 사용자가 반복 요청을 수행할 수 있고 모델 및 요청 `max_tokens`는 유지되는지 검증한다.
- 입력만 무제한, 출력만 무제한인 혼합 구성이 반대쪽 양수 한도를 계속 강제하는지 검증한다.
- 기존 양수 quota와 동시 출력 예약 테스트가 계속 통과하는지 검증한다.
- quota 0 사용자가 있는 DB의 시작 migration이 반복 실행 가능한지 검증한다.
- 관리 화면의 기본값, 최소값, `Unlimited` 표시를 검증한다.
- 관련 회귀 테스트 후 전체 `npm.cmd test`를 실행한다.
